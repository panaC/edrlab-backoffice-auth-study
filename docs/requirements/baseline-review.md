## Purpose

This document records the historical step-by-step review of each former `RB-*` requirement in the retired Phase 2 requirements baseline. It checks whether each baseline requirement was sufficient, correctly scoped, and not broader than the validated `FS-*` interpretation it supported ([Feature requirements review](./feature-requirements-review.md#coverage-review), [Feature scope review](./feature-scope-review.md)).

This review has been superseded by the consolidated root `FEATURE-REQUIREMENTS.md` list. It remains as a validation trail for why former `RB-*` material was kept, refined, split, removed, or marked as an assumption or open question during consolidation ([Feature requirements specification](../../FEATURE-REQUIREMENTS.md), [Project governance](../../PROJECT-GOVERNANCE.md#phase-2---requirements-and-risk-framing), [AGENTS](../../AGENTS.md#documentation-rules)).

## Review Method

Each `RB-*` review step records:

| Field | Meaning |
| --- | --- |
| `Reviewed requirement` | The baseline requirement being reviewed. |
| `Concordance` | Whether the requirement is supported by the immutable feature specification, the validated feature-scope review, cited guidance, or a user-provided requirement. |
| `Verdict` | `Correct`, `Insufficient`, `Too broad`, or `Needs rewording`. |
| `Scope decision` | Whether to keep, refine, split, remove, or defer the requirement. |
| `Consolidation implication` | What happened to the former baseline material during consolidation. |
| `Status` | `Pending`, `Validated`, or `Needs follow-up`. |

This review remains Phase 2 work: it may refine requirements, assumptions, risks, and open questions, but it must not select a final vendor, product, architecture, token strategy, implementation stack, or production recommendation ([Project governance](../../PROJECT-GOVERNANCE.md#phase-2---requirements-and-risk-framing)).
